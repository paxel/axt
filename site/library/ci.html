A library lives in a repository of its own, so its CI does not run the suite from a clone of the specification's repository. It runs the suite of the AXT release it conforms to, from that release's archive. The pin is what proves the version the library states.

The release archive

Each AXT release publishes an archive of its tagged tree, such as axt-0.1.0.tar.gz of v0.1.0. It holds the specification, the types, the vectors, the conformance suite and the reference relay, under one directory, axt-0.1.0/. The release also carries a build provenance attestation of the archive.

The steps

The steps are those of conformance/README.md, section "Running the suite in a library's repository":

  1. Pin. The library pins the release and the SHA-256 of its archive. Moving to a new AXT version is a deliberate change of the pin.
  2. Verify. The CI downloads the archive, checks its SHA-256 against the pin and checks the release's build provenance attestation: 
    gh attestation verify axt-0.1.0.tar.gz --repo paxel/axt
    Then it extracts the archive.
  3. Run. In the extracted directory, it installs what the runner needs from the archive's uv.lock and runs the suite against the library's adapter: 
    uv sync
uv run python conformance/run.py -- <the library's adapter>

The runner exits with 0 only when every vector it ran passed, so a failing vector fails the job (conformance.md, section 7.1).

Note

The runner runs only the categories the adapter names, and names the others as not run. A green job proves conformance only when the adapter names at least the nine categories every library implements (What a library implements).

Stating the version

The library's README and package metadata state the AXT version it conforms to; the pin proves it (conformance/README.md). When the pin moves to a new release, the stated version moves with it.

Keys in the vectors

Every key, secret and certificate in the vectors is a test value of keys.md, section 7.1. They are for tests only and are never used outside tests (conformance.md, section 7.3).
