When two apps connect, each sends its manifest: the types it takes, in which versions, and one sentence for each on what it does with the records. The other app offers only what fits, and shows its user your sentence before the user chooses what to send.

What you decide

The manifest is one axt.Manifest (manifest, section 3). These fields are the app's own statement:

FieldWhat it says
app_nameThe name the app gives itself, such as Old Brain Fix, shown to the other app's user
app_urlAn https page about the app, or null
takesThe types the app takes, each by full name, with a range of versions and a purpose sentence
any_typeWhether the app takes every other type, with a purpose sentence of its own
sendsThe types the app may send, for display, and whether it takes proposals for each; or null

The other fields, the revision, the envelope formats, the encryption key and the relay, are about how messages reach the app rather than what it takes (sections 3.2, 3.8 to 3.10). Every device of an owner has a manifest of its own (section 1).

The types you take

Each entry of takes names one type (section 3.3):

  • By full name, exactly. Never through aliases, a similar name or similar fields. If your app takes another app's type through an alias of its own schema or a converter, that type's full name is an entry of its own. axt.example.v1.Note and axt.example.v2.Note are two entries.
  • A range of versions. min_version and max_version state which versions you want, not which you can decode: every version within a major version resolves against every other. Set min_version above 1 only when you need a field that earlier versions lack, and leave max_version null.
  • A purpose sentence for each entry (below).

A manifest names each full name at most once in takes, and holds at most manifest.takes entries (section 4). An app that takes no type still sends a manifest, with an empty takes (section 5.1).

Any other type

With any_type, your app takes every type whose full name is not in takes, in every version, and shows records of a type it does not know from their description (section 3.5; Describe the fields). It covers only names that takes does not name: a type in takes in a version outside its range does not fit, even with any_type, since the entry left those versions out on purpose.

A type with full name N in version V fits a manifest (section 5.2):

  1. if takes has an entry for N, when V is within its range; its sentence is the entry's;
  2. otherwise, if any_type is not null; its sentence is that of any_type;
  3. otherwise not.

Purpose sentences

The purpose sentence is one sentence in English on what your app does with the records. It should name the type and what the app makes of it, so that it reads on its own, such as "An Appointment becomes a Reminder." or "Any other type becomes a searchable Note." (section 3.6).

  • It is one line of plain text, not empty, within manifest.purpose. No markup is interpreted in it (section 4).
  • purpose_translations gives the sentence in other languages, keyed by language tag, such as de, never en. The English sentence is always there, so every app has one to show.
  • The other app picks the sentence in its user's language, and the English one when none matches: a user who reads de-AT gets the de sentence, and one who reads fr-CH and fr gets the English one if there is no fr.

The sentence is what the sending user reads before choosing what to send (section 5.3), so it says what happens to their records in words a user understands.

What you send

sends lists the types your app may send, each with the versions it writes, or is null when the app does not say (section 3.7). It is for display: the other app may show its user what your app can send, and it limits nothing you offer. The one exception is proposals: true on an entry says that your app takes proposals of changes to its records of that type (Proposals).

A fit is not an acceptance

A sender offers only types that fit the receiver's manifest, and may offer fewer, such as only those its user chose. The receiver still confirms or declines each offer (section 5.4): it declines a type that does not fit its current manifest, may decline any type with NOT_WANTED, and may keep its user's answer for a sender and a type so as not to ask again (protocol, section 5.2).

When the manifest changes

The manifest changes when what the app takes changes: an update adds a type, the user turns one off, the app adds a language (section 6). Each change gets a higher revision.

  • A type that no longer fits is no longer offered, updates and deletions included. The records sent before stay at the receiver.
  • When it fits again and is accepted, the sender should send the current state of each record of the type it sent before.
  • A changed purpose sentence is shown the next time the sender's user chooses what to send.

A file has no connection. Its writer puts in only types that fit the manifest it keeps of the file's reader, if it keeps one; its reader applies no record whose type does not fit its own manifest (section 7).

The example

cat-a-log takes Pets and says what it sends; Old Brain Fix takes Appointments, Tasks and Notes by name and any other type (section 10.1). Old Brain Fix's entries: 

"takes": [
  {"type": "axt.example.v1.Appointment", "min_version": 1, "max_version": null,
   "purpose": "An Appointment becomes a Reminder.",
   "purpose_translations": {"de": "Ein Termin wird zu einer Erinnerung."}},
  {"type": "axt.example.v1.Task", "min_version": 1, "max_version": null,
   "purpose": "A Task becomes a Note with a Reminder.",
   "purpose_translations": {"de": "Eine Aufgabe wird zu einer Notiz mit Erinnerung."}},
  {"type": "axt.example.v1.Note", "min_version": 1, "max_version": null,
   "purpose": "A Note becomes a Note.",
   "purpose_translations": {"de": "Eine Notiz wird zu einer Notiz."}}
],
"any_type": {
  "purpose": "Any other type becomes a searchable Note.",
  "purpose_translations": {"de": "Jeder andere Typ wird zu einer durchsuchbaren Notiz."}
}

When cat-a-log offers to Old Brain Fix, a user who reads de-AT sees (section 10.2):

TypeFits bySentence shown
axt.example.v1.Petany_typeJeder andere Typ wird zu einer durchsuchbaren Notiz.
axt.example.v1.Appointmentthe entry in takesEin Termin wird zu einer Erinnerung.
axt.example.v1.Measurementany_typeJeder andere Typ wird zu einer durchsuchbaren Notiz.
axt.example.v1.Documentany_typeJeder andere Typ wird zu einer durchsuchbaren Notiz.

The other way round, a Note does not fit cat-a-log: it names no Note and takes no other type, so Old Brain Fix does not offer one.

Note

The app name and the sentences are what one installation says about itself. The key identifies the app; the name does not (section 2).
