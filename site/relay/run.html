The reference relay is one Python program, relay/axt_relay.py, with no dependency beyond the standard library. You start it with a storage directory and a few options, directly or in a container, and put a TLS proxy in front of it.

Note

The reference relay is a reference and a test oracle, not a production server. Its own HTTP server is not hardened against slow or many clients; the proxy in front keeps it away from the network (relay.md, section 7.2). Anyone can run a relay: AXT has no default relay operator, and each app chooses its relay (transports.md, section 5).

What you need

  • Python 3.11 or later, or a container engine such as Podman or Docker.
  • A directory for the relay's storage. The relay creates it if it is missing.
  • A host name with a certificate, served by a reverse proxy that terminates TLS. Apps reach a relay only over HTTPS. See Put a proxy in front.

Start it with Python

The command of relay/README.md:

python3 relay/axt_relay.py --storage /var/lib/axt-relay --base-path /axt/ --client-address-header X-Forwarded-For

The relay listens on 127.0.0.1, port 8080, and serves plain HTTP to the proxy. At start it logs one line with the address, the port and the base path it listens on. With the base path /axt/ and a proxy for relay.example.org, the relay's base URL is https://relay.example.org/axt/; apps append the paths of transports.md, section 5.2 to it.

--client-address-header takes each client's address from the header the proxy sets. Without it, every client has the proxy's address and all of them share one rate limit.

The options

python3 relay/axt_relay.py --help lists them; relay.md, section 7.1 explains them.

OptionDefaultMeaning
--storage DIR(required)The storage directory; created if missing
--host HOST127.0.0.1The address to listen on
--port PORT8080The port to listen on; 0 for one the system picks, which the start line names
--base-path PATH/The path of the base URL, beginning and ending with /, such as /axt/
--quota-bytes N67108864The room of a mailbox, 64 MiB; an empty mailbox always takes one message
--max-waiting N1000Lists that may wait at the same time; beyond it a list answers at once
--rate-requests N600Requests per minute per client address; 0 for no limit
--rate-creations N20Mailboxes created per hour per client address; 0 for no limit
--client-address-header NAMEnoneTake the client address from the last value of this header, set by the proxy, such as X-Forwarded-For
--no-access-logoffLog no line per request
--testoffTest mode; never in production

The limits behind --quota-bytes, --max-waiting and the rate options are on Limits and storage; the log is on Keep the logs within the rules.

Never in test mode

With --test, the relay has a clock that starts at 0 and that anyone can set with PUT /_test/now. Whoever sets it far ahead has the relay delete every message. Test mode is for the conformance vectors and the relay's tests only (relay.md, section 8). Without it, the relay uses the system's clock and /_test/now answers 404.

Start it in a container

relay/Containerfile builds an image with relay/ as the context. With Podman: 

podman build -t axt-relay relay/
podman run -d --name axt-relay -p 127.0.0.1:8080:8080 -v axt-relay:/data \
    axt-relay --base-path /axt/ --client-address-header X-Forwarded-For

With Docker, build with:

docker build -t axt-relay -f relay/Containerfile relay/

What the image does (relay.md, section 7.3):

  • It is based on python:3.13.18-slim-trixie, pinned by its digest.
  • It always starts the relay with --host 0.0.0.0 --port 8080 --storage /data: the relay listens on port 8080 on every address of the container. Options after the image name are passed to the relay as well.
  • The relay runs as the user 10001 and keeps its mailboxes in the volume /data. A directory mounted at /data instead of a volume must be writable by the user 10001.

-p 127.0.0.1:8080:8080 publishes the port on the host's loopback address only, so that only a proxy on the same host reaches the relay. This matters: when the relay takes the client address from a header, it must be reachable only through the proxy, since a client could otherwise set the header itself (relay.md, section 7.2).

Stop it

The relay stops on SIGTERM and SIGINT. Every write is atomic, so it can be stopped at any time, also by a crash or a full disk: a message is either held whole or not at all (relay.md, section 5.3). At the next start it reads its index of mailboxes and messages from the storage again.
