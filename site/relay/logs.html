A relay sees mailbox ids and client addresses. Together they tell who fetches from which mailbox, so the rules on logs keep secrets out of every log and keep lines with both for no more than 7 days.

The rules

For every relay (transports.md, section 5.7):

  • It never logs mailbox secrets or the value of Authorization headers.
  • It should not log mailbox ids together with client addresses, and deletes every log entry that holds both within 7 days.
  • It keeps no message beyond the holding time, also not in a backup.

A request path holds the mailbox id, so a log line with a path and a client address holds both.

What the reference relay logs

The relay logs to its standard error, one line per event, with the time in UTC (relay.md, section 6):

  • at start, the address, the port and the base path it listens on;
  • for each request, unless --no-access-log: the client address, the action (create, remove, put, list, fetch, delete, or the method), the status code, and the bytes of the message put or fetched;
  • for a request that cannot be parsed, or that times out: the client address, malformed and the status code;
  • for a failure of the storage or of the program: the error with its traceback, without a client address.

It never logs the value of Authorization, a mailbox secret, the request line or any content, and never a mailbox id or a message id in a line with a client address. A traceback can name a path in the storage, and with it a mailbox id, but never with a client address. No line of the relay holds both, so the 7-day rule applies to none of them.

--no-access-log drops the line per request. The client addresses of the access lines are the ones the proxy passes, when the relay reads them with --client-address-header.

What the proxy logs

The proxy is where the rules are easy to break. Many proxies log request paths with client addresses by default: in their access log, and in their error log for a request that fails. nginx and Caddy both do. For the proxy (relay.md, section 6, and section 7.2):

  • Never log Authorization.
  • Turn the access log off, or log no path.
  • Keep the error log for at most 7 days.
  • Delete every line that holds a request path and a client address within 7 days.

The examples on Put a proxy in front follow this: the nginx example sets access_log off, and Caddy writes no access log unless told to. Both still write an error log, which you keep for at most 7 days.

What the relay learns

Even without logs, a relay learns the mailbox ids, the size of each message, when it is put, fetched and deleted, and the addresses of the clients that do so. It learns no key and no content: the messages are sealed (transports.md, section 5.7). What it keeps on disk is on Limits and storage.
