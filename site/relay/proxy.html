Apps reach a relay only over HTTPS. The reference relay serves plain HTTP, so it runs behind a reverse proxy that terminates TLS, and it must not be reachable by apps without that proxy.

What the proxy does

The rules are in relay.md, section 7.2, built on transports.md, section 5.7. The proxy:

  • serves TLS 1.3 or TLS 1.2 as RFC 9325 recommends them, with a certificate that apps can check as for any HTTPS server;
  • accepts request bodies of at least transports.sealed_message, the largest sealed message (transports.md, section 5.6);
  • passes Content-Length and Authorization to the relay unchanged;
  • waits longer for the relay's response than a list may wait for a message, transports.list_wait (relay.md, section 3.3);
  • never logs Authorization, and keeps no line with a request path and a client address for more than 7 days (Keep the logs within the rules);
  • when the relay takes the client address from a header, sets that header itself. The relay is then reachable only through the proxy, since a client could otherwise set the header.

The proxy also keeps the relay's own HTTP server, which is not hardened against slow or many clients, away from the network. Where the proxy supports HTTP/2, it offers it to apps; the relay itself speaks HTTP/1.1.

The client address

Behind a proxy, every request comes from the proxy's address. The relay keeps its rate limits per client address, so without more, all clients share one limit. Name the header in which the proxy passes the client address with --client-address-header, such as X-Forwarded-For. The relay takes the last value of that header, the one the proxy added (relay.md, section 4.3).

Example: Caddy

The configuration of relay/README.md for Caddy, which obtains the certificate itself and writes no access log unless told to. Replace relay.example.org with your host name: 

relay.example.org {
	reverse_proxy /axt/* 127.0.0.1:8080
}

Example: nginx

The configuration of relay/README.md for nginx, with the certificate in files of your own:

server {
    listen 443 ssl;
    http2 on;                        # nginx 1.25.1 or later
    server_name relay.example.org;
    ssl_certificate     /etc/ssl/relay.example.org.crt;
    ssl_certificate_key /etc/ssl/relay.example.org.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    access_log off;

    location /axt/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header X-Forwarded-For $remote_addr;
        client_max_body_size 17m;
        proxy_read_timeout 75s;
    }
}

client_max_body_size 17m is 17 MiB, above transports.sealed_message, and proxy_read_timeout 75s is above transports.list_wait. access_log off keeps the access log from holding request paths with client addresses.

The relay behind either

Both examples send the requests under /axt/ to the relay on 127.0.0.1, port 8080, and pass the client address in X-Forwarded-For. Start the relay to match: 

python3 relay/axt_relay.py --storage /var/lib/axt-relay --base-path /axt/ --client-address-header X-Forwarded-For

The relay's base URL is then https://relay.example.org/axt/. This is the URL an app names in its manifest (manifest.md, section 3.10).
