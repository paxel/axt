AXT, Avro eXchange Transfer, is an open standard that lets small, independent apps exchange typed records with each other. Version 0.1.0 is released; below 1.0 a later version may still change things in incompatible ways.

The problem it solves

Most small apps keep their data in their own format. To move it into another app, the user types it again, or someone writes a converter for that one pair of apps. AXT gives such apps a common way to hand records to each other.

The example the specification uses throughout: cat-a-log, a pet log, keeps a vet appointment for Mimi, a pet. It sends the appointment to Old Brain Fix, which turns it into a reminder. Neither app needs to know the other's internals. They only agree on the record's type, here the example type axt.example.v1.Appointment.

What travels

  • Typed records. Every record type is described by bricks, typed fields put together, from which its Apache Avro schema is derived (Typed fields, section 9). A record is one datum of a type, with a stable id and a rising version (Records, section 1). Avro 1.12 schema resolution applies, so two apps can hold different versions of a type (Envelope, section 6).
  • Signed messages. Every message is an axt.Envelope, signed with the sending installation's Ed25519 key (Envelope, section 2; Keys, section 2).
  • Example types. The standard brings eight example types, such as Note, Task, Appointment and Person, so that apps can exchange without agreeing on types first (Types, section 7).

Three ways to exchange

AXT defines three transports. An app need not support all of them (Transports, section 1).

TransportHow it worksSpec
File An AXT file, an Avro object container file of signed messages, sent through any messenger, mail or file share. A file has no way back to its sender, so nothing acknowledges it. Transports, section 2
Local network One app shows a QR code with its key and address, the other scans it and connects. The connection is TLS 1.3, and a HELLO message binds it to the scanned key. Transports, section 3 and section 4
Relay A sealed mailbox: it holds end-to-end encrypted messages until their owner fetches them, and holds each for the holding time transports.holding. It sees neither their content nor their type. There is no default operator: each app chooses its relay, and anyone can run the reference relay. Transports, section 5; Relay

Who this documentation is for

This site is for the people who build on the standard itself: those who design what an app exchanges, those who write an AXT library, and those who run a relay. If you write an app and use an existing library, the library's own site is the place to start; the Libraries page lists them.
